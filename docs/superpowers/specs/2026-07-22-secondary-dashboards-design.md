# 收集箱、季度追踪与年终总结仪表盘设计

日期：2026-07-22

## 1. 背景

当前 Today 页面已经具备无登录工作区、任务与项目完整 CRUD、本地持久化、Supabase 服务端网关和软删除能力。侧栏中的“收集箱”“季度追踪”“年终总结”仍只有入口，没有对应页面，并会产生未匹配路由提示。

本阶段补齐三个可用页面。用户选择视觉方案 B：页面内部采用更鲜明的独立仪表盘结构；外层继续保留第一版 Huly 风格的深色工具栏、项目侧栏、浅色主工作区和 AI 右侧面板。

## 2. 目标

- 收集箱成为真实的任务整理入口，复用现有任务 CRUD。
- 季度追踪支持季度目标完整 CRUD、排序、状态和进度维护。
- 年终总结根据任务与季度目标实时生成，不增加独立总结记录。
- 本地网关与 Supabase 网关保持能力一致。
- 所有删除继续采用软删除。
- 桌面端和手机端保持可用、可读、可操作。

## 3. 非目标

- 不增加登录、注册或多租户界面。
- 不连接真实 Supabase 环境，不执行迁移。
- 不调用 MiniMax 或其他外部 AI。
- 不引入 Objective/Key Result 多层 OKR 模型。
- 不实现自动进度计算、协作、评论或附件。

## 4. 数据模型

新增 `QuarterGoal`：

```ts
type QuarterGoalStatus = 'active' | 'completed' | 'paused'

type QuarterGoal = {
  id: string
  ownerId: string
  quarter: string       // YYYY-Q1 至 YYYY-Q4
  title: string
  description: string
  progress: number      // 0 至 100 的整数
  status: QuarterGoalStatus
  sortOrder: number
  createdAt: string
  updatedAt: string
  deletedAt: string | null
}
```

`WorkspaceDocument.version` 升级为 `2`，新增 `quarterGoals` 数组。本地读取版本 1 数据时自动补充空数组并迁移为版本 2，保留所有现有项目和任务。

默认演示数据增加三个 `2026-Q3` 目标，使默认季度进度保持约 68%。季度目标删除只设置 `deletedAt`，不影响项目或任务。

## 5. 领域派生

共享领域层提供纯函数：

- 按季度筛选和排序有效目标。
- 计算季度平均进度、目标总数、风险目标数与完成目标数。
- 按年份统计任务完成数、任务完成率、目标平均进度和里程碑数。
- 里程碑由已完成季度目标和当年已完成任务派生。
- 项目完成分布只统计未软删除项目与任务。

年度任务集合定义为：到期日期属于目标年份的有效任务；没有到期日期时，以创建年份判断。完成数只统计该集合中 completedAt 属于目标年份的任务，完成率以年度任务集合总数为分母。年度目标集合为 quarter 年份与目标年份一致的有效季度目标。

风险目标定义为：状态为 `active`，进度低于季度时间进度 20 个百分点以上。时间进度由注入的当前日期计算，测试使用固定日期。

## 6. 数据访问与服务端

`WorkspaceGateway` 增加：

- `createQuarterGoal`
- `updateQuarterGoal`
- `deleteQuarterGoal`
- `reorderQuarterGoals`

本地网关继续使用同一 localStorage 文档，支持版本迁移、校验、软删除与排序。工作区模型提供对应状态方法，并沿用保存中、错误提示、提交后刷新和乐观排序机制。

Supabase 新增 `quarter_goals` 表：

- 固定 `owner_id` 过滤。
- `quarter` 格式约束。
- `progress` 范围约束。
- 状态枚举约束。
- 活跃记录与排序索引。
- 启用 RLS，不增加匿名访问策略。
- Service Role 通过 Nuxt 服务端仓储访问。
- `reorder_quarter_goals` RPC 校验 ID 集合并一次性更新排序。

Nuxt API 增加：

- `POST /api/quarter-goals`
- `PATCH /api/quarter-goals/:id`
- `DELETE /api/quarter-goals/:id`
- `POST /api/quarter-goals/reorder`

输入使用 Zod 校验，错误继续映射为现有 `WorkspaceError` 语义。

## 7. 页面设计

### 7.1 收集箱 `/inbox`

顶部仪表盘展示：待整理、今日新增、无项目任务。

主区使用紧凑任务表，提供文本搜索、完成状态和优先级筛选。任务创建默认归属收集箱；编辑、完成、移动项目、排序和软删除复用现有任务弹窗与操作菜单。

“整理建议”只根据空项目、优先级和到期时间生成本地规则提示，不使用 AI 文案冒充模型结果。

### 7.2 季度追踪 `/quarter`

默认显示 `2026-Q3`，并允许在已有季度之间切换。顶部展示季度总进度、目标数量、风险目标和剩余天数。

目标使用卡片网格。卡片展示标题、说明、进度条、状态与更新时间。页面支持新增、编辑、手动调整进度、状态切换、排序和软删除。新增与编辑统一使用目标弹窗。

空状态直接提供“创建季度目标”操作。

### 7.3 年终总结 `/review`

默认展示 `2026`。顶部使用大数字展示完成任务数、任务完成率、季度目标均值和里程碑数。

主区提供季度趋势、项目完成分布和里程碑时间线。图表使用本地 SVG/CSS，不引入新的图表依赖。所有数据实时派生，不持久化总结结果。

没有足够数据时，分别引导用户创建任务或季度目标。

## 8. 视觉规则

- 外层 Huly 框架不变。
- 页面内部采用用户选择的独立仪表盘方案 B。
- 大数字和图表只用于真实指标，不做装饰。
- Today 使用的紫色作为主强调色；青色表示健康进展，橙色表示风险。
- 卡片圆角和阴影比 Today 略强，但分隔线、字体和控件尺寸保持同一系统。
- 桌面端保留 AI 面板；手机端隐藏侧栏与 AI 面板，指标改为两列，底部导航固定。
- 支持键盘焦点；减少动态效果，不增加无意义动画。

## 9. 加载、错误与空状态

- 首次加载显示与页面结构一致的轻量占位。
- 网关错误使用现有工作区错误提示，不吞掉异常。
- Supabase 配置不完整时继续降级到本地模式并显示数据源标签。
- 保存期间禁用重复提交。
- 每个空状态提供一个明确的下一步操作。

## 10. 测试策略

严格遵循红—绿—重构：

- 领域测试：Schema、版本迁移、季度指标、年度指标和风险计算。
- 本地网关测试：目标 CRUD、排序、软删除和版本 1 迁移。
- 模型测试：目标操作、刷新和失败回滚。
- Supabase 仓储测试：固定 owner 过滤、字段映射、软删除和排序 RPC。
- API 契约测试：路由存在、Zod 校验与错误映射。
- SQL 契约测试：表、约束、RLS、索引与 RPC。
- 组件测试：目标弹窗、目标操作菜单、三个页面关键状态。
- 浏览器烟测：收集箱任务操作、季度目标新增/更新/软删除、年终指标联动。
- 视觉验收：1600×1000 桌面截图和 390px 手机截图。

最终必须重新运行完整单元测试、Nuxt TypeScript 检查和生产构建。

## 11. 验收条件

- 三个侧栏入口均有真实路由，不再产生未匹配路由提示。
- 收集箱任务操作刷新后仍保留。
- 季度目标完整 CRUD、排序与软删除在本地模式可用。
- Supabase 代码和 SQL 与本地网关契约一致，但不访问真实数据库。
- 年终指标会随任务或目标变化更新。
- 桌面端和手机端没有阻断操作的溢出或遮挡。
- 全量测试、类型检查和生产构建通过。
