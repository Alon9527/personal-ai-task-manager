# Supabase 项目与任务 CRUD 设计方案

日期：2026-07-22  
状态：设计已确认，等待书面规格复核

## 一、目标

将 Today 页面中写死在组件里的演示数组替换为可测试的数据层，支持项目和任务的完整 CRUD、手动排序、完成状态切换及可恢复删除。

应用在没有 Supabase 配置时必须能够完整运行；以后切换到服务端 Supabase 数据源时，不需要重写界面层。

## 二、本期范围

本期包含：

- 项目的创建、读取、编辑、软删除和手动排序。
- 任务的创建、读取、编辑、软删除、完成状态切换、重点/稍后移动和手动排序。
- 带初始演示数据的浏览器本地存储后端。
- Nuxt 服务端 API 和 Supabase REST 数据仓库；未配置时保持休眠。
- 可用于 Supabase 的 PostgreSQL 迁移与种子 SQL。
- 动态计算 Today 指标、任务分组及项目任务数量。
- 编辑表单、操作菜单、删除确认、加载状态、空状态和错误提示。

本期不包含：

- 登录、注册、退出和找回密码。
- 回收站及恢复界面。
- 真实 MiniMax API 调用。
- 多用户协作与并发编辑。
- 在真实 PostgreSQL 或 Supabase 项目中执行并验证迁移。

## 三、总体架构

界面组件不直接依赖具体存储方式，而是统一依赖 `WorkspaceGateway` 数据网关接口。`useWorkspace` 组合式函数负责数据加载、任务分组、指标计算、数据变更和错误状态。

浏览器侧提供两种网关实现：

1. `LocalWorkspaceGateway`
   - 默认启用。
   - 将带版本号的工作区文档保存到 `localStorage`。
   - 第一次运行时自动导入当前演示项目和任务。

2. `ApiWorkspaceGateway`
   - 当 `NUXT_PUBLIC_DATA_BACKEND=supabase` 时启用。
   - 只调用 Nuxt 服务端 API，不直接访问 Supabase。

Nuxt 服务端 API 调用 `SupabaseRepository`。该仓库使用 Nuxt 自带的请求能力访问 Supabase REST 和 RPC 接口。Supabase URL 与服务端密钥保存在私有运行时配置中，不会发送到浏览器。本期不新增运行时依赖。

数据源选择是显式的：

- 默认使用本地模式。
- 选择 Supabase 但私有配置不完整时，不发起网络请求，继续进入本地演示模式并提示原因。
- 一旦已经成功从 Supabase 加载工作区，后续请求失败时不自动切换到本地模式，避免形成两套相互分叉的数据。

## 四、领域数据模型

### 4.1 项目 `Project`

- `id`：UUID 字符串。
- `ownerId`：所有者 UUID。
- `name`：非空名称。
- `color`：经过校验的十六进制颜色。
- `sortOrder`：非负整数排序值。
- `createdAt`：ISO 创建时间。
- `updatedAt`：ISO 更新时间。
- `deletedAt`：可空的 ISO 软删除时间。

### 4.2 任务 `Task`

- `id`：UUID 字符串。
- `ownerId`：所有者 UUID。
- `projectId`：可空的项目 UUID。
- `title`：非空标题。
- `description`：描述。
- `priority`：`low`、`medium`、`high` 或空。
- `dueDate`：可空的 ISO 日期。
- `dueTime`：可空的本地时间。
- `isFocus`：是否属于今日重点。
- `sortOrder`：非负整数排序值。
- `completedAt`：可空的 ISO 完成时间。
- `createdAt`：ISO 创建时间。
- `updatedAt`：ISO 更新时间。
- `deletedAt`：可空的 ISO 软删除时间。

所有网关方法默认过滤已经软删除的记录。本地种子数据、服务端运行时配置和 SQL 种子数据共用一个固定的演示用户 UUID。

暂不登录时仍保留 `ownerId`，以后加入认证只需要替换固定所有者及服务端鉴权，不需要改变页面数据契约。

## 五、数据网关操作

`WorkspaceGateway` 提供以下方法：

- `loadWorkspace()`：加载工作区。
- `createProject(input)`：创建项目。
- `updateProject(id, patch)`：编辑项目。
- `deleteProject(id)`：软删除项目。
- `reorderProjects(orderedIds)`：重排项目。
- `createTask(input)`：创建任务。
- `updateTask(id, patch)`：编辑任务。
- `deleteTask(id)`：软删除任务。
- `setTaskCompleted(id, completed)`：切换完成状态。
- `reorderTasks(group, orderedIds)`：重排分组内任务。

删除项目时，项目及其所有未删除任务必须在同一次原子操作中软删除：

- 本地存储模式通过一次工作区文档更新完成。
- Supabase 模式通过一次 RPC 数据库事务完成。
- 界面必须先显示确认框，并明确提示受影响的活动任务数量。

任务分组规则：

- 已完成：`completedAt` 不为空。
- 今日重点：未完成且 `isFocus=true`。
- 稍后处理：未完成且 `isFocus=false`。

快速添加默认在“收集箱”项目中创建一条“稍后处理”任务。手动排序使用整数 `sortOrder`；网关一次性重写受影响分组的排序值。

## 六、Supabase 数据库与安全设计

迁移 SQL 创建 `projects` 与 `tasks` 两张表，包含：

- UUID 主键。
- 创建、更新和软删除时间。
- 手动排序字段。
- 数据校验约束。
- 所有者查询索引。
- 活动记录部分索引。
- 从任务到项目的外键。

迁移还会创建：

- 自动维护 `updated_at` 的触发器。
- 项目及其任务级联软删除的事务函数。
- 项目和任务批量排序的事务函数。

安全规则：

- 数据表启用 RLS。
- 不提供匿名读取或写入策略。
- Nuxt 服务端使用私有 `service_role` 密钥访问数据库。
- 每次查询和修改都必须增加固定 `owner_id` 条件。
- 私有密钥不得进入浏览器端代码或公共运行时配置。

这能阻止浏览器匿名直连数据表，但本期 Nuxt API 本身还没有用户认证。因此 Supabase 模式在加入登录之前只适用于本地开发或其他受控环境，不建议直接公开部署。

种子 SQL 写入：

- 收集箱项目。
- 当前侧栏中的三个演示项目。
- 当前 Today 页面中的演示任务。
- 固定演示用户 UUID。

种子数据使用固定主键，并通过冲突处理保证重复执行不会生成重复记录。

## 七、界面调整

保留现有 Huly 风格应用外壳及响应式布局，仅替换数据来源并补齐操作入口。

新增或调整：

- `TaskEditorDialog`：复用同一表单创建或编辑任务。
- `ProjectEditorDialog`：复用同一表单创建或编辑项目。
- `DeleteConfirmDialog`：软删除前明确确认。
- 任务行菜单：编辑、移到重点/稍后、上移、下移、删除。
- 项目菜单：编辑、上移、下移、删除。
- 顶部和侧栏的“新建任务”按钮打开任务编辑器。
- 保留内联快速添加。
- 指标卡片和项目数量根据活动数据动态计算。
- 显示“本地演示”标识，并说明因配置缺失而降级的原因。
- 加载时显示骨架屏。
- 空分组显示带操作入口的空状态。

排序使用上移和下移按钮，不引入拖拽依赖，使鼠标、键盘及手机端获得一致行为。

## 八、状态管理与错误处理

以下操作使用乐观更新：

- 完成状态切换。
- 重点/稍后移动。
- 项目与任务排序。

`useWorkspace` 在执行前保留旧快照。持久化失败时恢复快照并显示错误提示。

创建、编辑和删除操作在持久化成功后才更新可见状态，避免出现重复记录或记录提前消失。

使用现有 Zod 校验：

- 领域记录。
- 表单输入。
- 带版本号的本地存储文档。

发现损坏的本地数据时：

1. 将原始内容保存到带时间戳的备份键。
2. 创建新的演示工作区文档。
3. 向用户提示已保留损坏数据备份。

本地存储空间不足或序列化失败时，保留最后一份有效的内存状态。

服务端和 Supabase 错误统一转换为以下应用错误：

- 校验失败。
- 记录不存在。
- 数据冲突。
- 服务不可用。
- 未预期错误。

保存失败时，表单保持打开并显示简洁提示。

第一版采用“最后写入者生效”。冲突检测及多人协同编辑不在本期范围内。

## 九、Nuxt 服务端 API

服务端提供面向资源的接口，包括：

- 获取、新建和编辑项目。
- 获取、新建和编辑任务。
- 项目软删除。
- 任务软删除。
- 任务完成状态切换。
- 项目和任务批量排序。

每个处理器都必须：

- 校验输入。
- 在服务端注入固定演示 `owner_id`。
- 返回领域模型格式的 JSON，不直接暴露数据库字段格式。
- 将数据库错误转换为统一应用错误。

本地模式下不调用这些接口，因此本期开发与验证不需要任何网络请求。

## 十、测试策略

实施采用红—绿—重构的测试驱动流程。

### 10.1 数据网关契约测试

覆盖：

- 项目与任务 CRUD。
- 完成状态切换。
- 软删除。
- 删除项目时级联软删除任务。
- 项目和任务排序。

### 10.2 本地数据网关测试

使用 happy-dom 的真实 `localStorage`，覆盖：

- 第一次运行导入种子数据。
- 重新加载后恢复数据。
- 损坏数据备份与重建。
- 本地存储空间不足。

### 10.3 工作区状态测试

覆盖：

- 任务分组。
- 指标统计。
- 乐观更新。
- 持久化失败后的状态回滚。

### 10.4 Supabase 数据仓库测试

使用可注入的请求传输层，不发起真实网络请求，验证：

- REST 与 RPC 路径。
- 固定所有者过滤条件。
- 请求及响应字段映射。
- 数据库错误转换。

### 10.5 组件测试

覆盖：

- 快速添加。
- 新建和编辑对话框。
- 完成状态切换。
- 删除确认。
- 上下排序。
- 动态项目数量和指标。
- 空状态。
- 本地演示模式标识。

保留现有应用外壳与 Today 页面测试；仅在批准的动态行为改变预期时更新断言。

## 十一、验收命令

完成前必须重新执行并检查完整输出：

```bash
pnpm test
pnpm typecheck
pnpm build
```

本地可以验证 SQL 文件结构及数据仓库调用契约，但在真实 PostgreSQL 或 Supabase 中执行迁移之前，不能声称数据库迁移已经通过实库验证。

## 十二、验收标准

- 没有 Supabase 配置和网络时，应用以本地模式正常启动。
- 第一次运行显示演示项目和任务，刷新后数据仍然存在。
- 界面提供本期批准的全部项目和任务 CRUD 操作。
- 删除记录从正常读取中消失，但底层仍保留 `deleted_at`。
- 删除项目经过确认，并在一个原子操作中软删除所属活动任务。
- 排序结果能够持久化，并适用于鼠标、键盘和手机端。
- Today 指标、任务分组和项目数量随活动数据实时变化。
- Supabase 实现位于相同数据网关契约之后，私有配置只存在于服务端。
- 只有在单元测试、类型检查和生产构建取得最新成功输出后，才能宣布本期实现完成。
